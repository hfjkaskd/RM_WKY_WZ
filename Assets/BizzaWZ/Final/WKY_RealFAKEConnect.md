【四、玩法接入要求】

1. 启动与加载
沿用 InitWZ、框架 Loading 和正式网赚模式，核实 BIZZA_REAL_WITHDRAW 已启用；不符合时先报告，不自行修改宏或切换模式。

原 Loading 视觉同步到框架 LoadingPanel，只保留一套加载页。启动直接进入玩法，不接原主页及返回入口。

2. UI 与功能归属
玩法嵌入 RealGamePanel，保留框架货币、任务、提现等网赚 UI。
设置、胜利“恭喜获得”、失败及广告复活沿用框架流程；原货币、商店和结算系统不接入，不将原金币换算成网赚金额。
保留原玩法独有功能、操作反馈和提示。公共功能只留一个有效入口，显示的按钮必须绑定真实逻辑；隐藏旧 UI 前，迁走其中仍承担的教学、事件和提示挂载职责。
静态布局和绑定优先落在 Prefab/Inspector，适配安全区、不同分辨率和点击区域。弹窗打开至完全关闭期间不得点穿，关闭后不得遗留玩法输入锁。按钮的点击和拖拽事件尽量使用代码绑定，避免obfuz混淆问题

3. 框架调用与教学
区分“玩法调用框架”和“框架回调玩法”，避免递归、重复初始化或重复通知。
核实框架已有 NewPlayerEnter 调用，补齐玩法初始化但不重复新人赠送。
玩法真正就绪后调用 FlowModule.CanShowGuide()，基础教学实际完成后调用 FlowModule.NewPlayerGuideEnd()，BridgingUtil 承接对应玩法回调。
保留可见、可操作的基础教学和道具教学，正确处理目标位置、完成条件、存档及中断重进；原玩法没有基础教学时，报告并确认衔接方式。
禁止关闭 Teach_01、伪造完成状态或强拆 TransparentBlock 掩盖漏接。

4. 道具
沿用框架 UI、PropConfig、库存、获取和存档，接回原道具效果。
保留原图标、文字、锁定、数量、缺货、取消等样式，以及解锁、赠送、限制、选择、无目标提示和教学。
核实目标代码的使用与结束规则：

- 即时道具：cancelFunction=false，BridgingUtil.PropUse_X() 返回 true 后由框架自动收尾，不额外通知结束。
- 选择、异步或可取消道具：按现有机制设置 cancelFunction=true；实际成功调用 PropUtils.UsePropOver(itemType, false)，取消、失败或中断调用 PropUtils.UsePropOver(itemType, true)。这里的布尔参数是 breakFlow，不是 success。
- 未进入使用流程时，BridgingUtil.PropUse_X() 返回 false，不扣库存、不额外结束。
- 不得直接调用 BridgingUtil 的结束回调代替 PropUtils.UsePropOver；框架回调到玩法后，不得再反向通知结束。
- unlockFunction 与取消机制独立。

库存、次数、统计和结束通知只处理一次，原玩法不得重复扣除，框架已处理的取消不得重复通知。

5. 关卡、奖励与生命周期
通过 FlowModule.GameStart()、FlowModule.OpenGameWinPanel(...)、FlowModule.OpenGameLosePanel(...) 接关卡开始与胜败，通过 BridgingUtil.LoadGameLevel() 等框架回调承接重开与下一关；已有触发不重复添加。
保持原玩法的场景重载或原地重建方式：重开不加关，胜利只加一次；区分本次结算关卡、下一关进度和实际关卡配置。
存在合成、消除、收集完成事件时接 FlowModule.SynthesisLogic(...)，传真实剩余量及接口需要的位置，不按普通点击触发。
重开、切关时清理玩法旧对象、事件订阅、延迟任务、动画、道具选择和输入状态。分帧加载时，未就绪对象不得提前参与玩法、碰撞或动画。
